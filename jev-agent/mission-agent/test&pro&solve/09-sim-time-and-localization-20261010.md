# Sim 时间、定位辅助与恢复验证（2026-10-10）

本次优先修定位基础链路与相对运动；不验收 Full 冷启动、远距离货架导航、恢复后整条 Mission 续行。CPU 温度、相机配置告警未在本次处理。

## 1. 时间契约

| 用途 | 时间依据 | 保护条件 |
| --- | --- | --- |
| LiDAR/IMU、TF 配对 | 消息中的 ROS/sim 时间戳 | 不把接收时间冒充采样时间 |
| 初值后的点云积累 | 新扫描的 header 时间跨度，sim 默认 10 秒 | 唯一帧、最少帧数、有效点、方位回波覆盖、底盘静止 |
| 数据接收新鲜度 | monotonic 现实时间 | 与 ROS 源时间新鲜度分别检查 |
| 相对运动预算 | sim 使用 ROS 时间；real 保留现实时间 | sim 另设现实上限；暂停、回退、odom 过期均停止 |
| Recovery/Agent 心跳 | steady timer | 仿真暂停时仍能监控、取消和报告 |

不使用瞬时 RTF 乘除所有 timeout。RTF 波动时，直接测量扫描/仿真时间的推进更可靠。10 秒 sim 在 RTF 0.45 时约需 22 秒现实时间；积累窗口仍有 75 秒现实时间超时诊断，Recovery 的 sim 验证等待上限为 100 秒。

GICP 的 RMSE（例如 0.112）是几何残差，不是 RTF 或概率；不能用 RTF 对分数做倍率修正。低 RTF 会间接改变消息延迟、时间配对和窗口完整性。

## 2. 修正的问题

### LiDAR 与 FAST-LIO

- 原 adapter 用批次末尾时间作为起点，同时虚构一个发布周期内的逐点 offset，使扫描结束时间可能晚于真实采样时间。现在 header/timebase 是最早 slice 时间，offset 来自真实 slice 时间差。单个 slice 不再虚构未来采样时间。这里精度是 slice 级，并非仿真器没有提供的逐激光束时刻。
- 原 `line=i%40` 与 FAST-LIO 的四线配置不一致，会丢弃大量点。无真实通道信息时使用合法通道 0，不假造 40 个通道。
- FAST-LIO 使用 sensor QoS、小 LiDAR DDS 队列和较大的 IMU 队列；sim 按源时间限制待处理扫描积压，保留 IMU 历史用于惯性传播。
- sim 扫描结束时间采用真实 offset 的最大值，包含合法的零时长 slice，不再用平均扫描时长补到未来。
- `/fast_lio/timing` 提供最新 LiDAR/IMU、处理结束时间、队列深度、积压丢弃数和 `requires_restart`。
- 时间戳回退时，FAST-LIO 停止在旧滤波状态上继续输出，并明确要求重启；不是完整的自动时钟回退恢复。GICP 清除旧 epoch 的扫描和 hint，等待新初值。

重启和多项修复一起发生，不能把历史 14–17 秒积压归因于唯一一处代码。当前实测新鲜度和队列已改善；长时间 soak 与强负载仍需后续测试。

### IMU / wheel odom / 可信 pose

- IMU 确实进入 FAST-LIO 的预测及去畸变；GICP 使用新鲜、时间接近的 FAST-LIO 增量，不把它当地图绝对坐标。
- 当前 sim 的 `/wheel_odom` 是 Isaac 底盘运动计算，不是真实编码器模型。它提供 `odom -> base_footprint` 连续运动，用于相对任务和恢复传播；不使用 map 真值直接完成全局恢复。
- GICP 新增 `/gicp_loc/accepted_state`，把接受的 map 底盘 pose、同一 scan 时间的 odom 底盘 pose、时间戳和匹配指标放在一条消息中。
- Agent 不再把独立 score/pose 的到达顺序当作同一次估计，也不再用“收到定位消息时最新的 odom”代替同时间锚点。
- 原恢复把 LiDAR pose 用 yaw-only 外参换成底盘 pose，忽略俯仰和高度；之前检查中差异约 0.78 m。现在先做完整 3D 外参变换，再形成底盘平面锚点。
- 传播采用 `T_map_base(t0) * inverse(T_odom_base(t0)) * T_odom_base(t)`；发布前再次检查当前 odom TF、时钟、源时间和位移界限。移动期间有新鲜已接受估计时也更新可信锚点。
- odom 回退/不连续使锚点失效。人工初值本身不受“小幅位置修正”限制；自动 odom 外推仍有证据新鲜度和合理位移边界。

IMU 积分不是完全无偏：反馈门控修复后的整段观测约 181.1°，odom 约 178.6°。在一次底盘执行异常中差异更大。因此保留为独立辅助信号，不能以积分值覆盖 odom 或宣称传感器已经精确标定。

### 运动执行

- 原 `turn around` 固定 30 秒现实时间，在低 RTF 下不够。现在默认 30 秒 sim 预算、90 秒现实硬上限，时钟不推进超过 3 秒或 odom 过期则停止。
- 移动/转向不能在异常停止后用宽松终点容差改报成功；直线不再走到 75% 就算完成。
- 默认转角容差最大 0.05 rad（约 2.86°），记录和实际验收采用同一容差。
- 发现底盘驱动只检查指令转向角，不看实际关节到位。加入 `/joint_states` 实际转向反馈门控，忽略 arm-only 的部分关节消息；反馈缺失/过期/未对齐时不给驱动轮速度。
- 当前底盘进程曾以裸命令启动，未启用 sim 时间。已按正式 sim 配置重启；direct-cmd launch 分支也补传 `use_sim_time`。

### 恢复覆盖判定

受控中断测试中，原始 `/point_cloud` 和转换后的点云都持续缺少同样两个方位回波扇区（34/36），并非转换器漏了两个方向。要求 100% 回波扇区会无限等待，即使扫描时间已充分。

sim 回波覆盖阈值改为 90%。这不是“只扫 90% 就保证可定位”：必须同时满足 10 秒源时间、最少帧/点、静止及后续 GICP 残差、重叠和多帧健康证据。无回波不等于没有发射激光；目前仍没有逐束发射覆盖遥测。

另外修正 Recovery `Retry`：旧实现只清冷却/次数，在 `WAITING_OPERATOR` 状态仍保留旧 execution，因此按钮返回 `ok` 却没有重试。现在该状态下结束旧等待及请求，再允许新执行；不强行中断正在运行的执行器动作。旧锚点已经过期时依然需要人工式初值，不放宽时间门槛绕过它。
